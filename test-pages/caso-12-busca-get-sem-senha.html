Caso 12 — busca GET sem campo de senha

Resultado esperado: o envio é bloqueado. É o comportamento atual da ferramenta, que decide pelo protocolo do destino e não pelo tipo de dado enviado.

Finalidade do caso: medir falso positivo. Uma busca pública por GET não expõe dado sensível, mas é bloqueada do mesmo modo que um formulário de credenciais. Este caso existe justamente para registrar essa imprecisão na análise de resultados.

Este é o único caso sem input type="password", por definição: a ausência do campo sensível é o que está sendo testado. O formulário aponta para http://httpbin.org/post.
